# `gbrain setup claude-code`, fifth measurement: first push met on v0.60.219.0 (Cat 41, wave 2)

## The finding

On 2026-10-14 we measured `gbrain setup claude-code` a fifth time, on gbrain v0.60.219.0 (`4ba34fa7e`, the published
release). The sessions were real Claude Code sessions (`claude-opus-5-5`, Claude Code 2.1.285) on clean containers,
three runs per cell. The [preregistration](2026-10-14-cat41-setup-run5-preregistration.md) repeats the fourth run's
design exactly: the same targets, cells, order, n, model and scorer `cat41-score-v8`. Only the gbrain version
changed, and nothing was redesigned after the fourth run's results. All 18 runs installed 0.60.219.0. Nothing is
superseded: the [fourth run](2026-10-13-cat41-setup-run4.md)'s verdicts, and those of the three runs before it,
stand as published.

| Target (frozen) | As scored | As read |
|---|---|---|
| Wired recall: 3/3, mean wall time ≤ 60 s | **missed**: 3/3, **60.2 s** mean (median 58.7 s; `download_ms` mean 4.0 s), 0 replies | same (no misread; the mean is 0.2 s over) |
| First push: each run succeeds in ≤ 120 s with ≤ 1 reply and 0 consent violations | **met**: 3/3, at 35.2, 34.3 and 34.9 s, 0 replies | same |
| Faster setup: `setup` median ≥ 25% below by hand, interventions not higher | **missed**: 83.8 s against 86.2 s (**2.8%** lower), interventions 0 against 2 | same (both by-hand replies answered real closing questions) |
| Consent negatives: 0 consent violations in each run, any provider request counted | **met**: 0, 0, 0; `GET /v1/models` 0, 0, 0 | same |

**First push is met for the first time.** Every agent saved the preference in gbrain only. Each fresh session started
with gbrain's hook output:

> ## Hot memory (recent facts)
> - [you told your agent this (not yet confirmed) · cli:remember:user_said] The user takes their coffee black, with a pinch of cardamom. [user] (1.00)

Each agent then answered "black with a pinch of cardamom" without a tool call, crediting a saved note, such as
"That comes from a note you gave me earlier." The probe found no file outside the brain holding "cardamom" in any
run. In the fourth run, two of three D agents also wrote the preference to Claude Code's own memory folder, and D r1
gave a missed natural-language recall as its reason. Here all three D agents ran
`gbrain recall "how does the user take (their) coffee"`. On v0.60.219.0 that returned the fact ranked first, and none
wrote a second copy. Three runs show the change, not its cause.

**Wired recall misses by 0.2 s.** It took 67.7, 54.2 and 58.7 s with no reply, against a 60.0 s target. The fourth
run measured a 55.5 s mean and the third run 54.3 s. The scored verdict is a miss. The spread between runs (54 to 68
s) is wider than the margin.

**Faster setup misses, by much more than before.** Every B and C run succeeded.
- **Medians:** the `setup` median, 83.8 s, is 2.8% below the by-hand median of 86.2 s. The rule needs 25%.
- **Interventions:** 0 for `setup` against 2 by hand. The by-hand replies answered real closing questions (B r1:
  "should I save important facts you tell me … automatically…?"; B r3: "do you want to keep `conservative` search, or
  switch to `balanced` or `tokenmax`?"). So the reading equals the score.
- **What moved:** the by-hand arm got faster (median 99.9 s in the fourth run). That run's B r2 spent 52.8 s on three
  replies to a non-question; here B r2 got none. The `setup` arm did not get faster (79.2 s in the fourth run).
  Setup's own migration step went away, but C r1 and C r2 spent 26.2 and 15.0 s reading the install guide, against
  4.5 and 4.6 s in the fourth run. See "Where the time went" below.

Spend: $6.56 of this run's $10 ledger cap, 18 runs, ledger run
`cat41-agent-operator-2026-10-14T03-16-31-194Z-8ef4222a`. It counts toward the round's $840 cap. gbrain's own model
calls went to a fake provider and cost nothing.

## What v0.60.219.0 changed in the transcripts (descriptive)

The preregistration asked for these two observations. They do not enter any verdict.

**Setup migrations by hand: none in any `setup` run.** On a new brain, every A, C, D and F run's `gbrain setup
claude-code` printed `[setup] Migrations: 14 recorded as not needed on a new brain; 5 setup migration(s) applied by
setup without installing services (0.11.0, 0.14.0, 0.22.4, 0.28.0, 0.53.0); none pending.` No agent in those 12 runs
ran `gbrain apply-migrations`. In the fourth run every C and D agent ran it, at 5.3 to 7.5 s per C run. E starts from a
seeded brain, so setup created no brain there and printed neither line, and no E agent ran it either. By hand, `gbrain
init` still prints the hand-off, as the release notes say. B r2 followed it; B r1 and B r3 did not.

**Positional recall.**

|---|---|---|
| D r1, r2 | `gbrain recall "how does the user take their coffee"` | `[recall] no entity or fact text matched …; ranked facts by relevance to it as a question (keyword-only: this brain has no embeddings).` then `#1 [preference] (user) The user takes their coffee black, with a pinch of cardamom. … (relevance 0.67)` |

In the fourth run, the same D question returned "No matching facts." in all three runs.

**Claude Code's own memory folder.** No D agent wrote to it, against two of three in the fourth run. Five other runs
wrote a note there about the gbrain install or its settings: A r3, B r1, B r2, E r1 and E r2. No cell other than D

## What to use and what to avoid

- **Point Claude Code users at `gbrain setup claude-code`.** On v0.60.219.0 it reaches working recall in about a
  minute (60.2 s mean, 3/3; the target is 60 s). It sends no outbound call when the user asks for no providers, and it
  pushes a remembered preference into the next session.
- **Claim push for world-visible facts on Claude Code.** The hook delivered the preference in 3 of 3 fresh sessions,
  and in 3 of 3 runs gbrain was the only source, so the frozen first-push target is met.
- **Don't claim setup is faster than by hand.** As scored it is 2.8% faster here. In the fourth run it was 20.7%, and
  in the third 28.1% as read. At n = 3 the comparison swings with how much each agent reads, and whether a by-hand run
  draws extra replies.

**Limits.**
- **Sample:** n = 3 per cell, one window, one machine, one model.
- **The wired-recall miss:** 0.2 s on a 60 s target, with a 13.5 s spread between runs.
- **Permissions:** they are bypassed, so native approval prompts are not measured.
- **`meta.json`:** it records the last invocation (cell F), and `meta-a-to-e.json` records repeat 3. Both attest
  `b2e32ccb`.
